# คู่มือทบทวนกฎทางคลินิก

เพิ่มเครื่องมือ offline สำหรับเปรียบเทียบผลกับ labels ที่ผู้ทบทวนกำหนดไว้ล่วงหน้า: `scripts/evaluate_reference_cases.py` ดู schema/วิธีทดลองใน [บันทึกแก้ไขจากรีวิว](REVIEW_FIXES.md#เปรียบเทียบกรณีอ้างอิงแบบ-offline) ผลแสดง agreement/confusion counts พร้อม build/ruleset hashes และไม่คัดลอก raw inputs ออกมา ตัวอย่างที่แนบเป็น synthetic และทุกผลคง `clinical_approval=false`; ต้องกำหนด acceptance policy และประเมินกับข้อมูลอ้างอิงอิสระจริงก่อนอนุมัติใช้งาน

รุ่นนี้เป็นระบบสนับสนุนการคัดกรอง ไม่ใช่การวินิจฉัย และไม่ใช่ผลิตภัณฑ์ที่ผ่านการรับรองทางคลินิก การผ่าน unit tests ไม่ได้ยืนยัน sensitivity, specificity หรือความเหมาะสมกับผู้ป่วยของหน่วยงาน

ขอบเขตที่ผู้ใช้กำหนดสำหรับรุ่นนี้คือ **เรียนรู้และทบทวนผลภายในเครื่อง** ไม่เพิ่มฐานข้อมูลผู้ป่วย บัญชีผู้ใช้ ระบบลงนาม หรือ LIS/LIMS เพื่อจำลองความพร้อมงานบริการ ผลยังเป็นร่าง และกฎยังต้องคงสถานะตามหลักฐานที่มี ใช้ [แบบบันทึกทบทวนกฎ](RULE_REVIEW_TEMPLATE.md) เพื่อบันทึกแหล่งอ้างอิง กรณีที่ผู้ทบทวนกำหนดผลไว้ล่วงหน้า ความคลาดเคลื่อน และงานที่ยังค้าง ไม่มีการเติมชื่อผู้รับรองหรือสถานะผ่านให้โดยไม่มีการทบทวนจริง

ส่วน `thalab/ml.py` เปรียบเทียบความคล้ายกับต้นแบบสมมติ เป็นการสาธิต ไม่ใช่โมเดลที่ฝึกและประเมินจากชุดข้อมูลทางคลินิก คะแนนจากส่วนนี้ใช้เป็นความน่าจะเป็นหรือหลักฐานรับรองการวินิจฉัยไม่ได้ การปรับ UI หรือการผ่าน regression tests ไม่ได้เปลี่ยนข้อจำกัดนี้

## ขอบเขตและสมมติฐาน

- ไม่มี SOP สถาบัน แนวทางไทยฉบับที่ต้องยึด หรือ analyzer รุ่นเฉพาะส่งมา จึงคงค่าเริ่มต้นเดิมไว้ในโปรไฟล์ `draft_for_local_clinical_review`
- ขอบเขต `validation.ranges` เป็นขอบเขตตรวจข้อมูลกรอก ไม่ใช่ช่วงอ้างอิงปกติ ค่าที่อยู่นอกขอบเขตอาจสะท้อนหน่วยผิดหรือผลสุดขั้วที่ต้องทบทวน ไม่ควรถูกแก้ให้ปกติโดยอัตโนมัติ
- ข้อมูลขั้นต่ำเริ่มต้นคือ Hb, MCV และ MCH; ข้อมูลอื่นเว้นว่างได้ แต่มีผลต่อข้อจำกัดการแปลผล เมื่อไม่ระบุอายุ ระบบระงับเกณฑ์ CBC ที่ขึ้นกับวัยและกฎ HbA2/HbF ที่ต้องทราบอายุ ไม่เลือกโปรไฟล์ผู้ใหญ่โดยปริยาย ผู้ใหญ่ที่ไม่ระบุเพศจะไม่ใช้เกณฑ์เพศหญิงแทน เกณฑ์ที่ใช้ไม่ได้บันทึกเป็น `null` ในรายงาน โดยยังคงข้อเตือนเร่งด่วนจาก Hb ที่ใช้ได้
- เมื่อชุดกฎ screening ต้องใช้เกณฑ์ Hb/Hct ตามเพศ/การตั้งครรภ์ แต่ยังไม่ทราบการตั้งครรภ์ในเพศหญิง ระบบระงับการเทียบเกณฑ์ดังกล่าวและรายงาน `null` ไม่เลือกเกณฑ์หญิงไม่ตั้งครรภ์โดยปริยาย เกณฑ์เด็กที่ขึ้นกับอายุอย่างเดียวและข้อเตือน Hb ต่ำอิสระยังคงทำงาน ไม่มีการเปลี่ยนค่าตัดในการปรับนโยบายนี้
- เกณฑ์ตามอายุของ CBC เป็นเกณฑ์เดิมของโครงการ ต้องทบทวนแหล่งอ้างอิงและประชากรเป้าหมาย กฎจำเพาะจาก HbA2/HbF แบบผู้ใหญ่ถูกระงับในเด็กอายุต่ำกว่าเกณฑ์ `hb_fraction_min_age_years` (ค่าเริ่มต้น 1 ปี)
- HbA2 แยกวัด และ HbA2/E รวมเป็นคนละช่อง ไม่ใช้พีครวมแทน HbA2 เพื่อเรียก beta-thalassemia trait ระบบตรวจผลรวมจากชุดแยกและชุดพีครวมแต่ละชุด แม้ช่องแยกวัดจะกรอกไม่ครบ โดยไม่นำพีคซ้อนกันมาบวกซ้ำ และไม่บังคับให้ผลจากคนละวิธีต้องเท่ากัน เมื่อส่งทั้งสองชุดจะเตือนให้ตรวจต้นฉบับ
- ประวัติรับเลือด การตั้งครรภ์ ภาวะขาดธาตุเหล็ก การอักเสบ อายุ และชนิดเครื่องมือต้องได้รับการทบทวนในบริบทจริง
- EE score เดิมยังไม่เปิดการให้ข้อสรุป genotype เนื่องจากยังไม่มีหลักฐาน applicability ของสูตร/วิธีตรวจ/ประชากร การเปิดใช้ต้องเพิ่มข้อกำหนดและทดสอบโดยผู้รับผิดชอบ ไม่ใช่เปลี่ยน flag ใน JSON อย่างเดียว
- คะแนน 0–100 เป็นน้ำหนักสนับสนุนรูปแบบ ไม่ใช่ความน่าจะเป็นของโรค มีได้หลายรูปแบบร่วมกันและไม่ยืนยัน allele/zygosity/phase
- แบบจำลองคู่ใช้ parental allele สองชุด ระบบ alpha/beta แยกกัน ไม่ทำนายความรุนแรงจริงจากชื่อ allele กว้าง ๆ และไม่รวม variant ทุกชนิด
- `allele_panel.json` เป็นแผงสาธิต ขนาดแถบต้องตรวจสอบกับ primer และ SOP จริง ระบบรับสถานะ controls จากผู้ตรวจ ไม่วิเคราะห์ภาพ control อัตโนมัติ
- ไม่มีการเก็บประวัติผู้ป่วยหรือ audit trail แบบถาวร เพื่อคงข้อจำกัดไม่จัดเก็บข้อมูลระบุตัวบุคคล รายงานเป็นร่าง ยังไม่ลงนาม

## จุดที่แก้ได้โดยไม่แก้ Python

ไฟล์ `data/clinical_rules.json`:

| ส่วน | ความหมาย |
|---|---|
| `metadata` | เวอร์ชัน สถานะ แหล่งอ้างอิง คำชี้แจง |
| `validation.ranges` | `[ค่าต่ำสุด, ค่าสูงสุด, ชื่อและหน่วยภาษาไทย]` |
| `validation.required` | ข้อมูลขั้นต่ำก่อนให้ข้อสรุป |
| `thresholds` | จุดตัดต่าง ๆ ในหน่วยตาม schema |
| `age_thresholds` | รายการ `[อายุน้อยกว่า, ค่าจุดตัด]` เรียงอายุจากน้อยไปมาก |
| `adult_thresholds` | เกณฑ์ Hb/Hct ตามเพศและการตั้งครรภ์ |
| `scores` | น้ำหนักของสัญญาณเพื่อแสดงคะแนนประกอบ |
| `rules` | เงื่อนไขกฎและข้อความไทย: pattern/evidence/tests/genotypes/counseling |
| `messages` | ข้อความร่วมและข้อจำกัด |
| `partner_screening` | ข้อความเมื่อผลคัดกรองของคู่ครบ/ไม่ครบ/เป็นบวก/เป็นลบ |

แต่ละ rule มี `id` ที่ไม่ซ้ำ, `priority`, `score_floor` และเงื่อนไข `all`, `any`, `none` ซึ่งอ้างถึงสัญญาณที่มีอยู่ใน `logic/rules.py` ใช้ `all` เมื่อต้องเป็นจริงทุกข้อ, `any` เมื่อต้องมีอย่างน้อยหนึ่งข้อ, `none` เมื่อต้องไม่มีข้อใดเป็นจริง ไม่ใช้คำสั่ง Python หรือ eval ใน JSON

การเพิ่มแนวคิดสัญญาณใหม่ยังต้องให้ผู้พัฒนาร่วมทำ เพื่อให้เกณฑ์ input, validation, evidence และการทดสอบตรงกัน การแก้ตัวเลข/น้ำหนัก/เงื่อนไขที่ใช้สัญญาณเดิม/ข้อความทำได้จาก JSON

ไฟล์ `data/allele_panel.json` เก็บ `panel_id`, สถานะสาธิต และรายการ `alleles` ได้แก่ target_code, gene, method, expected_bp, nomenclature และ interpretation ต้องคงรหัสไม่ซ้ำและตรวจ nomenclature กับแหล่งอ้างอิง/ชุดตรวจจริงก่อนใช้งาน

## ขั้นตอนเปลี่ยนกฎ

1. บันทึกวัตถุประสงค์ เกณฑ์เดิม/ใหม่ ประชากรและเครื่องมือที่ใช้ พร้อมแหล่งอ้างอิงให้ผู้รับผิดชอบทบทวน
2. แก้ JSON และเพิ่ม `metadata.version` เมื่อเปลี่ยนกฎ การเปลี่ยนขอบเขต PCR ให้เพิ่ม `panel_id`
3. เพิ่มกรณีทดสอบที่ครอบคลุมจุดตัด ทั้งต่ำกว่า เท่ากับ และสูงกว่า รวมข้อมูลขาดหายและภาวะร่วม
4. รัน `python -m unittest discover -s tests -v` และเปรียบเทียบกรณีอ้างอิงที่ผู้เชี่ยวชาญทบทวนแยกจากผู้พัฒนา
5. รีสตาร์ตแอป ตรวจผลรายบุคคล/CSV/รายงาน รวมทั้ง ruleset version, SHA-256 hash และ thresholds_used
6. ผ่านการประเมินโดยหน่วยงานก่อนเปลี่ยนการใช้จากการศึกษา/ทบทวนเป็นงานบริการจริง

## แหล่งอ้างอิงประกอบ

- [ARUP Consult: Thalassemias](https://arupconsult.com/content/thalassemias) — แนวทางเลือกตรวจและข้อจำกัดของการแปลผล
- [GeneReviews: Alpha-Thalassemia](https://www.ncbi.nlm.nih.gov/sites/books/NBK1435/) — genotype, phase และบริบทการให้คำปรึกษา

เอกสารเหล่านี้เป็นหลักประกอบการออกแบบ ยังต้องระบุ Thai national guidance หรือ institutional SOP ที่หน่วยงานเลือกใช้ ไม่มีการอ้างว่าค่าเริ่มต้นทุกค่าได้รับการรับรองจากเอกสารข้างต้น

## โมดูล CBC/ภาวะโลหิตจางของ Hematologic Platform

โมดูลใหม่แยกจากกฎธาลัสซีเมียเดิม ใช้ `logic/cbc.py` และ `data/cbc_rules.json` ผลประเมินและรายงานเก็บ `ruleset_version`, `ruleset_hash`, `thresholds_used` และ `reference_intervals_used` ต้องอ่านเกณฑ์ตามโมดูลที่สร้างรายงาน ไม่ถือว่าคะแนนหรือการจัดระดับจากคนละโมดูลเทียบกันได้

โปรไฟล์เริ่มต้นจำกัดอายุ 18–65 ปี โดยเลือกเกณฑ์ Hb ตามเพศที่ระบุและสถานะไม่ตั้งครรภ์ที่ยืนยันตามข้อกำหนดของโปรไฟล์ อายุเริ่มต้น 18 ปีเป็นขอบเขตของแอป การใช้แหล่ง WHO ไม่ได้หมายถึงนำเกณฑ์ทุกประชากรของ WHO มาใช้แล้ว ขอบเขตและข้อจำกัดเพิ่มเติมอยู่ใน [HEMATOLOGY_PLATFORM.md](HEMATOLOGY_PLATFORM.md)

| ส่วนใน `cbc_rules.json` | วิธีทบทวน |
|---|---|
| `metadata` | เพิ่มรุ่นเมื่อแก้กฎ ตรวจแหล่งอ้างอิงและคงสถานะร่างจนมีหลักฐานของหน่วยงาน |
| `thresholds` | ตรวจอายุ หน่วย Hb (g/dL), MCV (fL), เกณฑ์ Hb และเกณฑ์แจ้งเตือน; ไม่ใช้เกณฑ์เตือนเป็นคำสั่งให้เลือด |
| `validation.ranges` | เป็นขอบเขตตรวจข้อมูลผิด/ผิดหน่วยอย่างกว้าง ไม่ใช่ช่วงอ้างอิงปกติหรือขอบเขตที่ผู้ป่วยเป็นไปไม่ได้ |
| `validation.reference_fields` | รายการค่าที่เทียบกับขอบเขตจากห้องปฏิบัติการ: WBC, platelets, RDW, ferritin และ absolute reticulocyte |
| `messages` | แก้ภาษาไทยได้โดยคงตัวแปร `{...}` ที่ข้อความนั้นรองรับ ตัวแปรใหม่ต้องแก้สัญญาข้อมูลและทดสอบร่วมกับผู้พัฒนา |

- ค่า Hb เริ่มต้นอ้างอิง [WHO 2024](https://www.who.int/publications/i/item/9789240088542) แต่ยังไม่ปรับตามความสูง การสูบบุหรี่ หรือปัจจัยก่อนวิเคราะห์อื่น ต้องทบทวนตามบริบท
- รูปแบบ MCV อ้างอิง [MSD: Evaluation of Anemia](https://www.msdmanuals.com/professional/hematology/approach-to-the-patient-with-anemia/evaluation-of-anemia) เพื่อเริ่มการประเมิน ไม่ใช่การยืนยันสาเหตุ
- Ferritin ต้องอ่านร่วมกับบริบทและการตรวจประกอบตาม [ARUP: Iron deficiency and inflammation algorithm](https://arupconsult.com/sites/default/files/Iron_Deficiency_Anemia_and_Anemia_of_Chronic_Disease_Inflammation_Algorithm.pdf) ค่าไม่ต่ำไม่ได้ตัดภาวะขาดธาตุเหล็ก
- ข้อมูลเด็ก การตั้งครรภ์ อายุเกินขอบเขต หรือบริบทไม่ครบจะไม่ใช้เกณฑ์ Hb ผู้ใหญ่โดยปริยาย; ข้อเตือน Hb ต่ำเชิงตัวเลขยังแสดงได้โดยไม่กำหนดระดับความรุนแรงแบบผู้ใหญ่
- ช่วงอ้างอิงที่ผู้ใช้กรอกต้องตรงกับอายุ วิธีตรวจ และหน่วย ระบบตรวจความถูกต้องของตัวเลข แต่ยังไม่รับรองว่าช่วงที่กรอกเหมาะกับผู้รับการตรวจ
- ไม่ใช้เพียง WBC/platelet count เพื่อสรุป leukemia, bleeding disorder หรือโรคไขกระดูก

หลังแก้ JSON ให้รีสตาร์ตแอปและรันทดสอบทั้งหมด รวมกรณีที่ขอบเกณฑ์ ข้อมูลขาด ข้อมูลผิด และกรณีนอกขอบเขต รายงานที่บันทึกในเซสชันยังเป็น snapshot ของกฎและข้อมูลเมื่อกดประเมินครั้งนั้น ต้องส่งแบบฟอร์มใหม่เพื่อใช้กฎใหม่

## กลุ่มงานเพิ่มเติมทั้ง 6 กลุ่ม

ทั้ง 6 กลุ่มมี engine และไฟล์กฎแยกกัน ใช้ schema/validation/report contract ร่วมกัน แต่ไม่ใช้เกณฑ์ทางคลินิกเดียวกันทั้งหมด เอกสารต่อไปนี้ระบุขอบเขตที่ทำงานจริง แหล่งต้นทาง และสิ่งที่ผู้รับผิดชอบต้องทบทวน:

| กลุ่มงาน | ไฟล์กฎ | เอกสารต้นทางและข้อจำกัด |
|---|---|---|
| WBC/differential | `data/white_cells_rules.json` | [WBC และ marrow](SOURCES_WHITE_MARROW.md) |

โครงสร้าง JSON ร่วมประกอบด้วย `metadata` (รุ่น สถานะ ขอบเขต คำชี้แจง แหล่งอ้างอิง), `fields` (ชนิด หน่วย ขอบเขตข้อมูล และตัวเลือก), `thresholds`, `messages`, `limitations`, `counseling` และ `examples` ค่า `unknown` คือไม่ได้ตรวจ/ไม่ทราบ ส่วน `none`, `no`, `negative`, `not_detected` เป็นคำตอบที่ระบุจริงตามความหมายของแต่ละช่อง จึงใช้แทนกันไม่ได้

สิ่งที่ต้องทบทวนก่อนใช้ในหน่วยงาน:

- ความเหมาะสมของ local reference/critical limits กับประชากร วิธีตรวจ หน่วย และคุณภาพตัวอย่าง; ช่วงตัวเลขที่ schema ยอมรับไม่ใช่ช่วงปกติ
- ความหมาย differential categories ที่ต้องไม่ซ้อนกัน และการแยก measured absolute counts ออกจากค่าคำนวณ
- ข้อเตือนจากอาการ ผล smear และผล molecular ที่ต้องไม่รอข้อมูลครบทุกช่องจึงจะแสดง
- เงื่อนไข PT/aPTT และ D-dimer: วิธีตรวจ ยารบกวน ความเสี่ยงก่อนตรวจ หน่วย/FEU-DDU และเส้นทางตรวจยืนยัน
- ขอบเขต ABO/RhD ตามชนิดส่วนประกอบเลือด รวมเงื่อนไขยืนยันตัวอย่าง ประวัติ antibody และ crossmatch; โปรแกรมไม่อนุมัติจ่ายเลือด
- สมมติฐานในการนับ manual differential, NRBC, ช่วง schistocytes ตามประชากร และเกณฑ์อายุ/คุณภาพตัวอย่างที่ห้องปฏิบัติการรับรอง
- ข้อสรุป marrow เป็นกลุ่มสมมติฐานสำหรับทบทวนหลักฐาน ไม่ใช่การกำหนด subtype ตาม WHO/ICC หรือยืนยันสาเหตุจาก marker เดี่ยว

การเปลี่ยนกฎเชิงโครงสร้าง เช่น เพิ่มเงื่อนไข เพิ่มชนิดข้อมูล หรือเปลี่ยนความหมายของตัวแปร ต้องแก้ engine และทดสอบควบคู่ ไม่ใช่แก้ข้อความเพียงอย่างเดียว ค่า normalization เปอร์เซ็นต์และข้อความยืนยันอาการที่มีความหมายตายตัวจะถูกตรวจไม่ให้เปลี่ยนจนขัดกับช่องรับข้อมูล

ชุดรายงานเก็บข้อมูลที่ใช้ เหตุผล ค่าคำนวณ ข้อเตือน เกณฑ์ รุ่นและ hash ของกฎในครั้งที่ประเมิน เป็นร่างไม่มีลายมือชื่อ การทดสอบซอฟต์แวร์ที่ผ่านไม่ได้แทนการประเมินความไว/ความจำเพาะ ความปลอดภัยทางคลินิก หรือการรับรองโดยหน่วยงาน
