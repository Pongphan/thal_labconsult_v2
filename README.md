## แพลตฟอร์มและโมดูล

รุ่นปรับปรุง 15 ตุลาคม 2026 ตรวจผลรวมเม็ดเลือดขาวจากค่าวัดและค่าคำนวณร่วมกันโดยนับแต่ละชนิดครั้งเดียว เก็บค่าร่างของแบบฟอร์มเมื่อสลับหน้าภายในเซสชัน และเปลี่ยนผล CBC/screening/โมดูลทั่วไปเมื่อกดประเมินเท่านั้น ส่วน PCR เป็นผลสดตามตารางและ controls ปัจจุบัน หน้าแรกมีแผนที่กลุ่มงาน จำนวนตัวอย่างจริงในคลัง และภาพทดลองผลรวม WBC สามสถานการณ์ในโทน pastel hematology

รายงาน screening JSON ใช้ `report_schema_version: 2` โดย `thresholds_used` เป็น object และรายการหลักฐาน/ข้อเสนอแนะเป็น array พร้อมข้อมูลคู่ครบถ้วน, `input_origin` และเวลาประเมินเดิม โปรแกรมที่อ่านรายงานรุ่นก่อนต้องเลิก parse `thresholds_used` ซ้ำเป็น JSON string

เตรียม [ชุดทดสอบกับผู้ใช้และแบบบันทึกผล](docs/USER_ACCEPTANCE_TESTS.md) แล้ว การทดสอบกับผู้ใช้จริงยังรอดำเนินการ ไม่รวมอยู่ในผล automated tests

| กลุ่มงาน | สถานะรุ่นนี้ |
|---|---|
| CBC ภาวะโลหิตจาง และเม็ดเลือดแดง | เปิดทดลอง: Hb/MCV ในผู้ใหญ่ตามขอบเขต และผลตรวจประกอบตามช่วงอ้างอิงที่ระบุ |
| ธาลัสซีเมียและความผิดปกติของฮีโมโกลบิน | เปิดทดลอง: คงการคัดกรองรายตัวอย่าง/CSV, Hb typing, PCR และการประเมินคู่ |
| ความผิดปกติของเม็ดเลือดขาว | เปิดทดลอง: differential → absolute counts, ข้อขัดแย้ง, ช่วงอ้างอิง และข้อเตือน ANC/ไข้/blast |
| ไขกระดูกและมะเร็งทางโลหิตวิทยา | เปิดทดลอง: สรุปหลักฐาน CBC/blast/flow/molecular/tissue และเส้นทางตรวจยืนยัน |
| เกล็ดเลือดและภาวะเลือดออก | เปิดทดลอง: platelet artifacts, PT/aPTT เทียบขอบเขตบน, fibrinogen และปัจจัยรบกวน |
| ภาวะลิ่มเลือด | เปิดทดลอง: บริบท pretest, D-dimer/หน่วย/FEU-DDU, imaging และข้อจำกัด thrombophilia tests |
| เวชศาสตร์การให้เลือด | เปิดทดลอง: ABO ตามส่วนประกอบเลือด, RhD/antibody/crossmatch gates และ suspected reaction |
| สัณฐานวิทยาและคุณภาพห้องปฏิบัติการ | เปิดทดลอง: บันทึก smear, manual differential, schistocytes ตามกลุ่มประชากร และ specimen quality |

รายละเอียดขอบเขต ลำดับงาน และแหล่งอ้างอิงอยู่ใน [แผนแพลตฟอร์ม](docs/HEMATOLOGY_PLATFORM.md)

## ความสามารถร่วมของ 6 กลุ่มงานใหม่

- แบบฟอร์มและข้อมูลสมมติจาก JSON; ช่องเริ่มต้นว่าง/ไม่ทราบ ประเมินเมื่อกดส่งเท่านั้น
- แสดงหน่วย ข้อผิดพลาด สิ่งที่พบ เหตุผล ข้อจำกัด และการตรวจเพิ่มเติม โดยไม่ใช้ค่าขาดหายแทนศูนย์หรือผลลบ
- เก็บข้อมูลแบบฟอร์มใน session เมื่อสลับหน้า/โหมด และล้างแยกกลุ่มงานได้
- รับค่าตัวเลขที่หน่วยตรงกันจาก CBC ล่าสุดได้เมื่อผู้ใช้กดเลือก โดยล้างหลักฐานอื่นในแบบฟอร์มก่อน ไม่คัดลอกข้อสงสัยเป็นผลยืนยัน
- รองรับ CSV สูงสุด 2 MB / 200 แถว มีแม่แบบ คู่มือรหัสตัวเลือก และไฟล์สาธิต; คงแถวข้อมูลผิดพลาด และไม่ส่งต่อชื่อ/HN/รหัสต้นฉบับ
- ดาวน์โหลด CSV ภาษาไทยและ JSON ทั้งรายตัวอย่างและรายชุด พร้อมค่าคำนวณ ข้อเตือน เกณฑ์ที่ใช้ รุ่นกฎ ลายนิ้วมือกฎ และข้อมูลที่ใช้ครั้งนั้น
- กฎ ข้อความ ขอบเขต และแหล่งอ้างอิงอยู่ใน JSON แยกกลุ่มงาน ไม่มี dependency เพิ่ม

ขอบเขตสำคัญ: ระบบไม่ลงนามผล ไม่อนุมัติจ่ายเลือด ไม่อ่านภาพเซลล์ด้วย AI ไม่คำนวณขนาดยา และไม่ใช้ผลตรวจเดี่ยวตัดโรคหรือจัดจำแนกมะเร็งขั้นสุดท้าย

## หน้าจอและธีม

- ธีมสว่างใช้สีพาสเทล ส่วนธีมมืดใช้พื้นสีน้ำเงินเทาและสีหัวข้อที่จางลง แยกการ์ด 8 โมดูลด้วยโรส ลาเวนเดอร์ ฟ้า ไลแลค พีช เหลือง คอรัล และมินต์ ปุ่มเมนูบน/ปุ่มย่อยและการ์ดหัวข้อใช้ palette เดียวกัน
- หน้าหลักแสดงภาพเม็ดเลือดเวกเตอร์ตกแต่ง ตัวนับ 4 กลุ่มหลัก/8 โมดูล/9 พื้นที่ทำงาน/กรณีสมมติ และแผนภาพเรียนรู้ครบ 8 โมดูล โดยนำส่วน “เลือกพื้นที่ทำงาน” พร้อมการ์ดโมดูลออกแล้ว กราฟแท่งนับตัวอย่างที่มีจริงในแอป ไม่ใช่ความชุกโรคหรือจำนวนผู้ป่วย
- เมนูด้านบนกลุ่ม **อื่นๆ** มีการ์ด **การประเมินผลด้วย AI** และ **การออกแบบใบรายงานผล** เรียงต่อด้านล่างจากสัณฐานวิทยาและคุณภาพ ใช้สีเขียวน้ำทะเลและครามตามลำดับ AI ยังอยู่ในแผนพัฒนา ส่วนการออกแบบรายงานเปิดต้นแบบข้อมูลสมมติได้ เป็นเครื่องมือเสริมแยกจาก 8 โมดูลเรียนรู้
- หน้าทำงานใช้ส่วนหัวกระชับเพื่อให้เข้าถึงแบบฟอร์มได้เร็ว แยกขั้นเตรียมข้อมูล กรอกผล ทบทวนข้อค้นพบ และส่งออกรายงาน ข้อผิดพลาดและข้อเตือนอยู่ก่อนรายละเอียดรอง
- ใช้แถบนำทางด้านบนโดยไม่มี sidebar แบ่งเป็น **หน้าหลัก**, **เม็ดเลือดแดงและความผิดปกติของเม็ดเลือดแดง** (CBC/ธาลัสซีเมีย/PCR), **เม็ดเลือดขาวและความผิดปกติของเม็ดเลือดขาว** (WBC/ไขกระดูกและมะเร็งทางโลหิตวิทยา), **อื่นๆ** (เกล็ดเลือด/ลิ่มเลือด/เวชศาสตร์การให้เลือด/สัณฐานวิทยาและคุณภาพ) ข้อมูลและผลใน session คงอยู่เมื่อสลับหน้า
- ขนาดฟอนต์หลักเพิ่มสองขั้นจาก 16 → 18 → 20 px หัวข้อแบบ rem ขยายตาม และข้อความที่กำหนดขนาดตายตัวรวมกราฟเพิ่ม 4 px
- ความสูงขั้นต่ำของปุ่มบนเพิ่ม 10% (52 → 57.2 px; จอแคบ 48 → 52.8 px) และขยายต่อได้ตามข้อความ การ์ดหัวข้อใช้ `calc-size(auto, size * 1.1)` เพิ่มความสูงตามเนื้อหาในเบราว์เซอร์ที่รองรับ; fallback เพิ่ม padding แนวตั้ง 10% โดยไม่ล็อกความสูงหรือตัดข้อความ ขนาดจริงขึ้นกับฟอนต์และการตัดบรรทัดด้วย
- ธีม Light/Dark กำหนดใน `.streamlit/config.toml` และเปลี่ยนได้จาก Settings ของ Streamlit ฟอนต์ใช้ชุดที่มีในเครื่อง ไม่มีการโหลดฟอนต์จากบริการภายนอก
- CSS ใน `ui/shell_styles.py` จำกัดอยู่กับ markup และคลาส `st-key-` ที่แอปตั้งชื่อเอง ส่วน `.stMainBlockContainer` ใช้เฉพาะจัดความกว้างและระยะขอบพื้นที่หลัก ไม่มีการครอบสีปุ่ม ฟอร์ม ข้อเตือน ตาราง หรือกราฟทั้งหมดด้วย selector ส่วนกลาง
- การ์ดและ navigation มีสถานะโฟกัสด้วยแป้นพิมพ์ รองรับการตัดบรรทัดและมี CSS สำหรับจอแคบ กราฟใช้คำอธิบายประกอบและธีมร่วมกับ PCR; การตรวจ headless ไม่แทนการตรวจภาพจริงบน desktop/mobile
- สีช่วยแยกหมวดและสถานะ ภาพตกแต่งและแผนภาพหน้าแรกไม่ใช่ภาพตรวจจริงหรือเกณฑ์วินิจฉัย แบบฟอร์มผู้ใช้แยกจากข้อมูลตัวอย่างสำหรับเรียนรู้

| กลุ่มงาน | สีประจำกลุ่ม |

## การเรียนรู้และภาพรวมโลหิตวิทยา

- หน้าหลักแสดงแผนภาพเรียนรู้ครบ 8 กลุ่มงานพร้อมตัวเลือกหัวข้อและกราฟจำนวนกรณีสมมติจากข้อมูลจริงในแอป กราฟนี้แสดงจำนวนสื่อเรียนรู้ ไม่ใช่ความชุกโรคหรือจำนวนผู้ป่วย แต่ละหัวข้อแบ่งเป็นภาพรวม/ลำดับการทบทวน ตัวอย่างจำลอง และขอบเขต/แหล่งเรียนรู้
- ภาพรวมแสดงลำดับ 3 ขั้น ประเด็นเรียนรู้ ข้อจำกัด แหล่งอ้างอิง และลิงก์เข้าพื้นที่ทำงานที่เกี่ยวข้อง
- เริ่มที่ธาลัสซีเมียและคงกราฟเดิมทั้งสองกราฟ อีก 7 กลุ่มงานมีกรณีสมมติที่คำนวณจาก engine เดียวกับพื้นที่ทำงาน เปิดแสดงได้เมื่อต้องการ
- กราฟภาพรวมธาลัสซีเมียแยกสีตามกลุ่มโกลบินและแสดงคำอธิบายเมื่อชี้ที่จุด ตำแหน่งจุดไม่ใช่คะแนนความรุนแรงหรือความเสี่ยง; กราฟข้อมูลจำลอง 6 รายแสดงระดับการทบทวนของกฎ ไม่ใช่ความชุกหรือความรุนแรงของโรค
- ตัวอย่างแสดงข้อมูลนำเข้า หน่วย สิ่งที่พบ เหตุผล ข้อเตือน แนวทางทบทวน และรุ่นกฎ ไม่คัดลอกข้อมูลหรือผลจำลองเข้าแบบฟอร์มผู้ใช้
- แก้เนื้อหาใน `data/learning_modules.json` ได้โดยไม่แก้ UI: แต่ละกลุ่มต้องมี `intro`, `focus` 3 ข้อ, `pathway` 3 ขั้น, `limitations` 2 ข้อ, `sources` และ `example_question` พร้อม `reviewed_on` ของชุดเนื้อหา ตัวโหลดตรวจความครบถ้วนตามทะเบียนโมดูลและรูปแบบลิงก์ก่อนแสดง
- วันที่ทบทวนเนื้อหาไม่ใช่การรับรองทางคลินิก ตัวอย่างและคำอธิบายยังต้องอ่านร่วมกับขอบเขตของแต่ละเครื่องมือ

## CBC และภาวะโลหิตจาง

- แบบฟอร์มว่างเป็นค่าเริ่มต้น มีข้อมูลสมมติให้เลือกและประเมินหลังส่งแบบฟอร์ม
- โปรไฟล์ Hb เริ่มต้นจำกัดอายุ 18–65 ปี ต้องทราบอายุ/เพศที่ใช้เลือกเกณฑ์; ในกรณีหญิงต้องระบุว่าไม่ตั้งครรภ์ ไม่เดาเกณฑ์ผู้ใหญ่แทนเด็ก การตั้งครรภ์ หรือข้อมูลที่ไม่ครบ
- แสดงสถานะ Hb และรูปแบบ MCV พร้อมเหตุผล การตรวจเพิ่มเติม และข้อจำกัด ไม่สรุปสาเหตุโรคจาก CBC อย่างเดียว
- รับ WBC, platelet count, RDW, ferritin และ absolute reticulocyte พร้อมช่วงอ้างอิงที่ห้องปฏิบัติการระบุ หากไม่มีช่วงอ้างอิงจะไม่สมมติว่าอยู่ในเกณฑ์ปกติ
- ดาวน์โหลด CSV ภาษาไทยและ JSON พร้อมข้อมูลที่ส่ง รุ่นกฎ ลายนิ้วมือกฎ และเกณฑ์ที่ใช้จริง; ข้อมูลอยู่ใน session memory
- กฎและข้อความอยู่ใน `data/cbc_rules.json` แยกจากกฎธาลัสซีเมีย ผลและการแจ้งเตือนของแต่ละโมดูลต้องอ่านตามขอบเขตของตนเอง

## ความสามารถโมดูลธาลัสซีเมียเดิม

- แบบฟอร์มภาษาไทย: CBC, ferritin, HbA2 แยกวัด, HbA2/E รวม, HbF, HbE, HbH, Bart, Constant Spring, OF/NESTROFT, DCIP และ HbH inclusion
- ตรวจข้อมูลตามขอบเขตที่กำหนดใน JSON; ค่าว่างแตกต่างจากศูนย์และผลลบ
- แสดงรูปแบบที่สงสัย จีโนไทป์ที่ยังไม่ยืนยัน เหตุผล ข้อจำกัด การตรวจเพิ่มเติม และประเด็นให้คำปรึกษา
- แยกคำเตือน Hb ต่ำรุนแรงออกจากชื่อรูปแบบ; กราฟและรายงานใช้ผลจากระบบกฎเดียวกัน
- CSV รายงานภาษาไทยแบบ UTF-8 BOM สำหรับ Excel, Markdown และ JSON มาตรฐาน (null แทน NaN)
- Batch CSV คงทุกแถว รวมแถวผิดพลาด; แทนรหัสต้นฉบับด้วยรหัสสมมติ; ไม่แสดงคอลัมน์นอก schema
- ส่งออกคุณลักษณะ ML และเปิดดูความคล้ายกับต้นแบบได้ในส่วนทดลอง คะแนนไม่ใช่ความน่าจะเป็น
- คงฐานข้อมูล allele, ตัวกรอง, กราฟ, ตารางการถ่ายทอด และการส่งออกของเดิม
- เพิ่มตาราง PCR ที่แก้ไขได้ การตรวจ controls ข้อขัดแย้ง ภาพเจลจำลอง และ CSV ร่าง

## ติดตั้งและเรียกใช้

เปิดบน Windows ด้วยการดับเบิลคลิก **`run.cmd`** แล้วเข้า `http://127.0.0.1:8501` เมื่อใช้ workspace ที่ติดตั้งแล้วไม่ต้องเปิดใช้งาน environment ด้วยตนเอง ตัว launcher ตรวจ imports และเวอร์ชัน dependencies ก่อนเปิด และบังคับรับการเชื่อมต่อเฉพาะเครื่องนี้

ติดตั้งครั้งแรกโดยใช้ CPython 3.12 แบบ 64 บิต:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

`ExecutionPolicy` ใช้กับโปรเซสนี้เท่านั้น ไม่เปลี่ยนนโยบายเครื่อง `setup.ps1` สร้าง environment ที่ยังไม่มี ติดตั้งเวอร์ชันจาก `requirements-lock-win-py312.txt` และไม่เรียกตัวติดตั้งเมื่อ environment ผ่านอยู่แล้ว หากไม่มี `py` ให้ระบุ `-Python C:\Python312\python.exe`

ชุดทดสอบปัจจุบันใช้ **Python 3.12.15 / Streamlit 1.65.0 / pandas 2.3.3 / NumPy 2.5.3 / Plotly 6.9.0** lockfile ครอบคลุม transitive dependencies ทั้ง 39 packages ใช้กับ Windows x86_64/Python 3.12; เป็นการล็อกเวอร์ชันโดยไม่มี wheel hashes ส่วน `requirements.txt` ระบุช่วงเวอร์ชันสำหรับการติดตั้งบนแพลตฟอร์มอื่นที่ต้องตรวจสอบแยก

macOS/Linux หรือ environment อื่น:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/check_environment.py
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest
.venv/bin/python -m streamlit run app.py --server.address=127.0.0.1 --browser.gatherUsageStats=false
```

ตรวจ runtime ด้วย `.venv\Scripts\python.exe -X utf8 scripts/check_environment.py --locked` เปลี่ยนพอร์ตด้วย `run.ps1 -Port 8507` หยุดด้วย `Ctrl+C` ก่อนเปลี่ยน dependencies หรือกฎ แล้วเปิดใหม่เพื่อให้ snapshot และ imports สอดคล้องกับ source ล่าสุด รายละเอียดการซ่อม environment หลังย้ายโฟลเดอร์และการส่งต่ออยู่ใน [LOCAL_SETUP.md](docs/LOCAL_SETUP.md) ผลตรวจและข้อจำกัดอยู่ใน [TEST_RESULTS.md](docs/TEST_RESULTS.md)

## ข้อมูลและความเป็นส่วนตัว

ไม่กรอกชื่อ HN เลขประจำตัว หรือข้อมูลที่ระบุตัวบุคคล รวมถึงชื่อไฟล์อัปโหลด ข้อมูลอัปโหลดและผลอยู่ในหน่วยความจำของเซสชัน แอปไม่เขียนผลตรวจลงดิสก์ ฐานข้อมูล log หรือ shared cache ปุ่มล้างข้อมูลใช้เริ่มเซสชันงานใหม่ ไฟล์ที่ผู้ใช้กดดาวน์โหลดจะถูกบันทึกบนเครื่องของผู้ใช้ตามการตั้งค่าเบราว์เซอร์

การแทนรหัสและตัดคอลัมน์ไม่ได้ตรวจพบข้อมูลระบุตัวบุคคลทุกชนิด ผู้ใช้ต้องนำเข้าข้อมูลที่ตัดการระบุตัวบุคคลแล้ว การใช้ภายในเครื่องกำหนด `server.address = "127.0.0.1"` และปิด usage telemetry; launcher ย้ำสองค่านี้เพื่อไม่ให้ environment variables เปลี่ยนขอบเขตการเชื่อมต่อโดยไม่ตั้งใจ

ไม่มีฐานข้อมูลประวัติผู้ป่วย ระบบบัญชีผู้ใช้ การลงนามรายงาน หรือ LIS/LIMS integration ตามขอบเขตเรียนรู้ภายในเครื่อง รุ่นนี้ยังไม่ได้ทดสอบผู้ใช้พร้อมกันหรือรับรองงานบริการจริง การเปลี่ยนไปใช้ผ่านเครือข่ายต้องออกแบบสิทธิ์ การเก็บข้อมูล และการรับรองตามบริบทใหม่

## การแก้กฎ

อ่าน `docs/CLINICAL_REVIEW.md` ก่อนแก้ JSON คงรหัสกฎ เพิ่มเวอร์ชันเมื่อเปลี่ยนเกณฑ์ และรันชุดทดสอบทุกครั้ง รีสตาร์ตแอปหลังแก้ clinical_rules, cbc_rules หรือ allele_panel เพื่อให้ defaults และ reference cache สอดคล้องกัน

กลุ่มงานใหม่ใช้ `data/<module_id>_rules.json` โดย `fields` กำหนดชื่อ/หน่วย/ชนิด/ขอบเขต/ตัวเลือก, `thresholds` กำหนดเกณฑ์, `messages` เก็บข้อความ, `metadata` เก็บขอบเขต/รุ่น/แหล่งอ้างอิง การเปลี่ยนเงื่อนไขชนิดใหม่ยังต้องแก้ engine และกรณีทดสอบร่วมกับผู้พัฒนา ไม่ใส่ Python หรือสูตรที่สั่งรันใน JSON

แหล่งและข้อจำกัดเฉพาะกลุ่มงาน: [WBC/Marrow](docs/SOURCES_WHITE_MARROW.md), [Hemostasis/VTE](docs/SOURCES_HEMOSTASIS.md), [Transfusion/Morphology](docs/SOURCES_TRANSFUSION_MORPHOLOGY.md)

แหล่งอ้างอิงประกอบการออกแบบ:

- [ARUP Consult: Thalassemias](https://arupconsult.com/content/thalassemias)
- [GeneReviews: Alpha-Thalassemia](https://www.ncbi.nlm.nih.gov/sites/books/NBK1435/)

แหล่งอ้างอิงเหล่านี้ไม่ใช่การรับรองน้ำหนักคะแนนหรือเกณฑ์เดิมทั้งหมดของโครงการ ต้องทบทวนกับ SOP/เครื่องมือของสถาบัน
